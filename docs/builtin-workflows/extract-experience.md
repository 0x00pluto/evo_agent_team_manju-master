# 提取经验

从 1～N 个项目（或同仓多段实践）抽取**共性**，写成项目无关的最佳实践：只提供操作指南与抽象方法论，指导下一步；不写死某一仓的路径、品牌、密钥或一次性事故。

由用户明确要求「提取经验 / 提炼最佳实践 / 抽跨项目共性」时触发；**不**在每次任务后自动跑。与 `post-task-reflect` 同为用户手动触发，职责不同（仓内删步升格 vs 跨项目共性），互不串联。

## 入口

打开本文件，按「日常步骤」落盘。入口不是 CLI。

## 参数

| 参数 | 说明 |
|---|---|
| 源项目 | 1～N 个路径或逻辑名（可读其 `AGENTS.md` / `docs/workflows` / `docs/faqs` / 相关脚本） |
| 主题 | 一句话：这次要抽哪类共性（例：浏览器会话生命周期、命令母版抽离） |
| 落盘目标 | 见下「落盘规则」 |

### 落盘规则

1. 先读本仓 `AGENTS.md`「提取经验落盘」节的 `experience_target`：
   - **已有值** → 直接用该路径，**不再追问**。
   - **无该节 / 无值** → **必须先问用户一句**：「公有经验落到哪个目录？不指定则用本仓 `docs/best-practices/`」。未得到回答 → **停**，禁止落盘。
2. 用户给出目录 → 写入（或更新）`AGENTS.md`：

```markdown
## 提取经验落盘

| 字段 | 值 |
|---|---|
| experience_target | <用户指定的目录绝对或相对路径> |
```

然后落盘到该目录。AGENTS 模板**不**预置空节；仅用户首次指定时创建。
3. 用户不指定 / 说「默认 / 本仓」 → 本仓 `docs/best-practices/<slug>.md`（目录不存在则创建）。**不要**因此写入 `experience_target`。
4. **禁止**因「上下文能写团队知识库」就静默写入团队 `最佳实践/`；团队库只在用户指定（或已记录的 `experience_target` 指向那里）时才写。

### 索引登记

| 落盘位置 | 登记 |
|---|---|
| 团队知识库 `最佳实践/` | 其上级 `index/doc_index.md`（若有） |
| 本仓 `docs/best-practices/` | 本仓 `docs/doc_index.md` |
| 其它自定义路径 | 同树若有 `doc_index.md` 或 `index/doc_index.md` 则登记；否则只落盘，并在回复说明未登记 |

## 日常步骤

```text
确认落盘目标（读 experience_target 或强制询问）
→ 列候选共性
→ 剥项目特异（路径/品牌/密钥/人名/一次性事故）
→ 写成「何时用/不用 + 操作指南 + 抽象原则」
→ 对照已有最佳实践：新建 or 升版合并
→ 落盘 + 登记索引
```

0. **确认落盘目标**：按「落盘规则」；未确认则停。
1. **列候选共性**：从源项目列出可复用的步骤、约束、失败模式；标「出现在几个源」。
2. **剥项目特异**：删掉本机绝对路径、真实密钥、仅某一客户/产品能懂的专名、单次事故复盘。样板来源可写在 frontmatter `source` 一句（相对路径或逻辑仓名），**正文**用「业务仓 / 权威仓 / 工作区」等角色词。
3. **成文结构**（对齐团队最佳实践习惯）：
   - 文档定位（abstract）
   - 何时用 / 何时不用
   - 操作指南（可逐步执行）
   - 抽象原则 / 硬约束
   - 与相邻文档的分工（如有）
4. **对照已有**：同主题已有文 → **合并升版**（改 `version` + `updated`），不要平行再造一篇重复文；无则新建，`version` 从 `1.0.0` 起。
5. **落盘**：按已确认目标写入；按「索引登记」写一行摘要。若本步新建了 `experience_target`，一并写入 `AGENTS.md`。

### 硬约束

- 只留**可指导下一步操作**的共性；单项目轶事进本仓 `docs/faqs/`，不进最佳实践。
- 禁止正文出现本机绝对路径、真实密钥、仅某一客户/产品专名。
- frontmatter **必须**含：`title`、`description`、`created`、`updated`、**`version`**（semver）、`tags`；可选 `source`。
- 升版：破坏性改约定 → MAJOR；新增章节/场景 → MINOR；措辞修正 → PATCH；并更新 `updated`。重大变更可在文末加 `## Changelog` 小节（不强制独立 CHANGELOG 文件）。
- **禁止**在未询问且无已记录 `experience_target` 时写入团队知识库或其它非本仓默认路径。

## 产物

- 一篇（或升版后的）最佳实践 Markdown（已确认的目标目录）
- 更新后的对应索引一行（若按规则应登记）
- 可选：本仓 `AGENTS.md` 新增/更新的 `experience_target`
- **不是**源项目的操作复述或聊天总结

## 失败排查

| 现象 | 处理 |
|---|---|
| 文里全是某仓绝对路径 / 产品名 | 剥特异；路径只留在 `source` 或删掉 |
| 只有一个项目的一次踩坑 | 写 `docs/faqs/`，本流结束或改主题后再抽 |
| 与已有最佳实践重复两篇 | 合并进旧文并升版，删掉重复新建 |
| 未改 `version` / `updated` 就改约定 | 补 semver 与日期后再算完成 |
| 每次任务后自动跑本流 | 停；本流仅用户明确要求时触发 |
| 未问落盘（且无 experience_target）就写了团队库或落盘 | 停；补问用户；若已误写则移到确认后的目标或本仓 `docs/best-practices/` |

## 测试

- 换一个未参与提炼的兄弟仓或新人，只读该最佳实践，能按「何时用」判断是否适用，并按操作指南走通主路径（无需打开源项目）。
- frontmatter 含合法 semver；按「索引登记」应登记的已登记。
- 无 `experience_target` 时跑本流会先问落盘；指定后 `AGENTS.md` 有该字段，再跑不再追问。

# MiniMax 音色编号与删除

同一把 MiniMax 密钥下，所有项目的克隆音色共用一份名额。后台列表没有删除按钮。`voice_name` 和 `description` 会在查询结果里出现，但克隆接口不接收这两项，克隆出来的声音它们一直是空的。日后能认出来的，只有创建时写入的 `voice_id`。

## 何时用

往这个账号新建、替换或删除一条克隆音色时。

## 何时不用

只用系统预置音色、不占克隆名额的合成。那种音色自带名字，不走这份编号。

## 操作指南

1. 新建前调用 `POST /v1/get_voice`，`voice_type` 为 `voice_cloning`。同一人、同一角色已经有一条还要用的编号，就复用，不要再克隆。
2. 必须新建时，`voice_id` 写成 `{项目}-{是谁}-{yyyyMMddHHmmss}`。
   - 字母开头。只用字母、数字、`-`、`_`。长度 8 到 256。不以 `-` 或 `_` 结尾。时间戳是数字，结尾仍然合法。
   - 减号只做三段之间的分隔。项目和是谁内部只用字母和数字，不用中文。项目用短英文。是谁用拼音或角色英文。
   - 已经能读的例子：`Show-Host-20261011143022`。
   - 已经在用、没有减号的旧编号继续复用，不要为了补减号再克隆。
3. 不要用 `V` 加随机串，也不要让接口自己生成 `moss_audio_…`。这两种从列表里看不出是谁。
4. 中文展示名只放在各项目自己的本地记录里。账号列表不靠它。
5. 换成新声音会再占一个名额。新编号仍按上面的形式写。旧编号如果没有成片还在用，立刻删除。
6. 删除调用 `POST /v1/delete_voice`，`voice_type` 为 `voice_cloning`，带上 `voice_id`。删掉的编号不能再用。

## 硬约束

- 克隆请求体没有 `voice_name` 和 `description`。不要依赖这两项出现在后台。
- 一个 `voice_id` 在账号里只能有一条。重复提交会失败。
- 名额是订阅配额。接口不能加名额。满了就删掉确认没用的，或提高订阅。
- 删除前先看本地成片清单。还被引用的编号删掉之后，那些成片再重配会失败。

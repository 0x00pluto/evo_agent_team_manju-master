# 漫剧操作台

本机页面：先在「加载脚本」用飞书链接、上传文本或粘贴正文之中的一种读入，再逐段选择「生成分镜」或「只配音」。确认后进入「生成提示词」。出镜名单由勾选锁定。DeepSeek 只写外貌、场景和运镜。「生成提示词」只出人物、场景和分镜。配音要等每个说话人（以及本集的旁白）绑到可用的声音之后。MP3 再打开或打包给后期。

业务仍是提示词生成与整集配音。操作台只是壳，不改画风，不给空镜再写一套无人分镜。

## 入口

```bash
cd /Users/peng.zhi/Documents/Codex/AI漫剧大师
.venv/bin/python scripts/run_studio.py --open
```

浏览器打开 `http://127.0.0.1:8767/`。只绑定本机。

同一套页面也可以作为 Dex Buddy 插件打开。仓库根上的 `plugin.manifest.json` 指向 `index.js` 和这份页面。列表和详情的图标、简介来自清单里的 `icon` 与 `description`。分类来自 `category`，插件市场按「流量密码」分段。插件里按钮优先走 `window.dex.call`，没有再退回 `window.hub.call`；浏览器里两者都没有则仍走本机 HTTP。业务还是 Python，不在 Node 里重写。

开发时不要把源码拷进 Dex Buddy 的 `plugins/`。任选一种：

```bash
ln -s "/Users/peng.zhi/Documents/Codex/AI漫剧大师" "/绝对路径/DexBuddy/plugins/manju-studio"
```

或在 Dex Buddy 仓库根把 `config.dev.example.json` 复制为 `config.dev.json`，写入：

```json
{
  "extraPluginPaths": [
    "/Users/peng.zhi/Documents/Codex/AI漫剧大师"
  ]
}
```

`config.dev.json` 只在未打包的开发版里生效。改 `index.js` 或页面后重启 Dex Buddy。侧边栏名字是「漫剧操作台」。

本仓开发时要有 `.venv`。清单里的 `runtime.python` 指向 `requirements.txt`。Dex Buddy 在开发目录直接用这份 `.venv`，不另外建环境，也不替你安装依赖。装进 Dex Buddy 之后，宿主按 `requirements.txt` 准备 Python，再用 `python -m src.studio.hub_worker` 跑源码。发给别人的包不带 `.venv`，也不带 `.env`。Python 还没准备好时，报「运行环境还没准备好」。

开发、软链接或 `config.dev.json` 挂进来时，`ctx.dirs.data` 就是本仓，`temp/` 和 `output/` 仍写在这里。从插件中心装进 Dex Buddy 之后，`ctx.dirs.data` 是用户数据目录 `plugin-data/manju-studio/`。覆盖安装不会把成片和 `temp/studio_facts` 清掉。`assets/` 仍从安装目录读。卸载插件时 Dex Buddy 不删这份数据。`dispose` 只结束 worker。

插件中心发版只改 `plugin.manifest.json` 的 `version`（`X.Y.Z`，不要前导 0），提交并推送，再打 tag `vX.Y.Z` 并推送。`v` 后面必须和清单版本相同。根上的 `dex-buddy-plugin.pack` 列出要装给同事的路径：清单、入口、图标、`requirements.txt`、`src/` 和 `assets/`。测试、文档和命令行脚本不进这份 zip。这不是已删除的 `dex-buddy-plugin-pack.json`，仓库根上还有那份旧文件时发布会失败。把仓库 `0x00pluto/evo_agent_team_manju-master` 和这个 tag 告诉 Dex Buddy 维护者，由他在 Actions 里运行 Publish Plugin。同事在插件中心安装，不要把下载地址发给他们。不要在本仓加调用 Dex Buddy 的工作流，也不要把密钥打进包。

在 Dex Buddy 里从侧栏底部「设置」选「漫剧操作台」。设置页按「提示词」「飞书」「配音」三组显示：提示词里填 DeepSeek 密钥、模型和接口地址，飞书里填 App ID 与 App Secret，配音里填 MiniMax 密钥，然后点「保存」。改了 `plugin.manifest.json` 里的设置声明后要重启一次 Dex Buddy。工作台把设置放进子进程环境，每次请求再带一份，所以改一项密钥不用重启常驻 worker。仓库里的 `.env` 只给本机命令行用，不进 zip。工作台注入的值优先，`.env` 不会盖掉它们。飞书文档用这两个应用凭证走开放平台读取。配音由本仓直接调用 MiniMax。窗口要能访问外网，页面上的字体和 Alpine 来自 CDN。

## 参数

| 参数 | 说明 |
|---|---|
| `--host` | 默认 `127.0.0.1`；其它地址拒绝启动 |
| `--port` | 默认 `8767` |
| `--open` | 启动后打开浏览器 |

页上不填密钥。提示词用本仓 `DEEPSEEK_API_KEY`。飞书读取用 `FEISHU_APP_ID` 和 `FEISHU_APP_SECRET`。配音用 `MINIMAX_API_KEY`。本机命令行把这几项写在 `.env`。

## 日常步骤

1. 启动操作台。开场停在「加载脚本」。
2. 在「脚本」里三选一，一次只用一种。飞书链接必须整段就是 wiki 或 docx，不读多维表格，也不从一段说明里搜链接。上传只接受 `.md` / `.markdown` / `.txt`，选定或拖入后只记住文件名，不立刻分段。粘贴是页内文本框。切换来源会清掉另外两种的内容，并清掉已有分段。
3. 分段方式在来源输入外面，加载前就能改。默认「按标题分段」：去掉配图后按整行 `【…】` 切开。切不出段时留在这一页，列表空白，并提示可以改用模型。选「让模型分段」时，DeepSeek 把原稿收成标准分段，提示词在 `src/prompt_templates/script_normalize.md`，调用在 `src/script_preprocess.py`。点「加载」的同时旧分段消失。等待时输入框下方有一条从左到右循环的流光条；按标题时说明正在加载脚本，用模型时说明正在让模型分段。成功后整表换成这次的结果。标题外面包了加粗星号也认。有「某人：台词」的段默认生成分镜，纯旁白默认只配音。角色说明放在第一段标题之前，口播要点表和配图不进列表。失败时列表保持空白并显示原因，上一次分段不会回来。改链接、正文、文件或分段方式也会立刻清掉列表和上一次错误。只改某一段的「生成分镜 / 只配音」不会清掉。
4. 有本次分段后点「下一步」，进入「生成提示词」。这一页只读显示每段标题和已选用途，不能在这里改选段。要改就点「返回」，脚本和选段还在，不会新开目录。点「生成提示词」用的是这次解析得到的正文，不再重读飞书。这一步不配音，也不读取声音列表。勾了生成分镜的段才生成分镜；一段对白超过约 72 字就按句拆镜。所有段的口播都进配音清单。没有说话人的句子记为「旁白」。DeepSeek 不决定出镜名单。说话人按脚本原名保留，不再收成「企业主 / 招商顾问」。缺 MiniMax 密钥时提示词仍可复制。生成进行中不能返回，也不能再点一次。失败留在这一页，不进入查看结果，也不发起配音。
5. 完成后是查看结果：人物三视图与特写、场景、分镜，每块单独「复制」，按这个顺序贴进即梦 / LibTV。然后是「角色声音」。上面是这一集的角色，下拉框只列出已经可用的音色，两个人可以选同一个。企业主、企业老板会默认对上 AI企业主，招商运营、招商顾问、招商主管会默认对上女招商主管，但只在那个声音已经可用时才写上；人手改过的选择不会被盖掉。下面是音色库：还不能用时点「生成可用音色」，可用之后可以「换成新声音」。库里没有合适的，再用「添加音色」。包内 `voice.json` 的 id 不会拿去合成。音轨须在 10 秒到 5 分钟、且不超过 20MB。
6. 全部绑好后点「生成配音」。没有 MP3 时配音页只有「生成配音」。配完之后才出现「打开所在文件夹」和「下载全部」。配音按 `01`… 试听。改某一句的字，点该条「重新配音」，只重配这一条，音色用该角色当前插槽的本账号 `voice_id`。单条下载，或「下载全部」成 zip。「打开所在文件夹」只打开这一集的 `voiceover` 文件夹。Mac 走访达，Windows 走资源管理器。没有绑定记录的历史集，重配沿用该条已经写下的 `voice_id`。
7. 查看结果点「返回」回到「加载脚本」。这次会话里还有分段就保留，不会自动打开「生成提示词」。第二页的「返回」只回到加载页改选段。要另起一份脚本，点左上角「AI漫剧大师」，来源和分段会清掉，已生成的结果仍留在历史记录里。生成提示词进行中点标题不会离开。历史记录仍直接打开某一次查看结果，不重建当时的分段。同一脚本再生成会新开目录。

同一时刻只跑一集。上传落在 `temp/studio_uploads/`。

## 产物

- `temp/studio_facts/<年月日-时分秒-名称>.json`
- `temp/studio_facts/<年月日-时分秒-名称>-voiceover.json`
- `temp/studio_facts/<年月日-时分秒-名称>-cast.json`（说话人指向插槽；没有口播句则不写）
- `voice-slots.json` 与替换后的样音 `voice-slots/<id>/sample.mp3`（本账号音色，覆盖安装不删）
- `output/<年月日-时分秒-名称>/` 提示词与 `voiceover/*.mp3`，例如 `output/20260929-095800-four-demo/`

这两份 JSON 是这一稿的临时事实，脚本不要了就可以连 `temp/studio_facts/` 一起删。汉阳造、光谷生物城的参考稿仍在 `assets/episodes/`。分镜里的参考图由程序写成「图1角色三视图；图2场景贴图；可选面部特写」，不交给模型填「无」。

同一脚本再跑会新开一个目录，不覆盖上一次。配音文件仍是 `01`… 序号。已知称呼沿用 `owner` / `advisor`，旁白是 `narration`，其余说话人用稳定短名。

## 失败排查

| 现象 | 处理 |
|---|---|
| 已有任务进行中 | 等当前集结束，或重启操作台 |
| 飞书读取失败 | 设置里填写飞书 App ID 和 App Secret；应用开通「查看新版文档」「查看知识库」，并被加进这篇文档或知识空间；链接是 wiki 或 docx |
| 脚本里没有【】段落，可以改用模型分段 | 在「分段」里改选「让模型分段」后再加载，或给每一段补上整行 `【标题】` |
| 没能把脚本整理成分段 | 模型改写了台词，或分段对不上原文；把口播改成清楚的句子后再加载 |
| 台词不在脚本原文里 | 出镜句必须来自勾了分镜的段；只配音的句子不能进分镜 |
| 超过 12 秒上限 | 单句超过约 72 字且没有句号时无法再拆，缩短这句后重跑 |
| 提示词有了但没有 MP3 | 先在「角色声音」把每行绑到可用声音；缺密钥时在设置或 `.env` 里填写 `MINIMAX_API_KEY`，再点「生成配音」 |
| 文件夹打不开 | 确认该集 `output/<主题>/voiceover/` 里已有文件 |

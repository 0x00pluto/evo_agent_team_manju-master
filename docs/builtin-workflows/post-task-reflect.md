# 任务后反思

仓级反思手册。目标：让下一轮同类任务更少依赖大模型、更少出错、更快，并删掉不该存在的步骤。顺序不可颠倒：先减法，后乘法。

**仅**在用户明确要求「反思 / 任务后回顾 / 跑 post-task-reflect」时触发（建议用户已验证本轮产物可用）。**禁止**在任务结束后自行启动。不要在聊天里另起一套反思散文。

## 入口

打开本文件，按「日常步骤」改仓。入口不是 CLI。

## 参数

| 参数 | 说明 |
|---|---|
| 本轮改动范围 | 改了哪些文件 / 脚本 / 工作流；有无可复跑过程 |
| 实际消耗 | 能数清的一项：步骤数 **或** LLM 调用次数（不要编 token） |
| 理论下限 | 同一验收标准下，最少的确定性操作（一条命令、一个脚本、一次断言） |
| 本轮是否失败 | 有无失败、重试、人工纠偏 |

## 日常步骤

顺序不可颠倒：

```text
算白痴指数
→ 1 删（存在性质疑）
→ 2 程序化（少依赖大模型）
→ 3 鲁棒（只给留下的必要步骤）
→ 4 加速
→ 有变更才落盘
```

### 0. 白痴指数

- **白痴指数** = 本轮实际消耗 / 理论下限
- **实际消耗**：步骤数或 LLM 调用次数（选能数清的一项）
- **理论下限**：同一验收下最少的确定性操作
- **读数**：
  - < 2：几乎贴下限；无失败则只扫一眼鲁棒，可跳过落盘
  - 2–5：走全透镜
  - &gt; 5：默认能删掉大约一半步骤

### 1. 删

对每一步问三条硬问题（匿名需求直接进删除候选）：

1. 谁要求这一步存在？（「最好检查一下」没有署名 → 候选删）
2. 删掉后，验收还能用程序 / 测试证明通过吗？
3. 本轮若提不出至少一项可删或可合并 → 默认删得不够，不是「已经最优」

只保留「删掉就会让产物无法验收」的步骤。

### 2. 程序化（少依赖大模型）

对**留下的**每一步：输入输出若能写成规则 / schema / 退出码 / 文件存在性 / 哈希 / 测试断言 → 抽到 `scripts/` 或 `tests/`，下次禁止再用 LLM 做这一步。

LLM 只留在非结构输入或无法用断言验收的判断。「脚本里仍在调 LLM」不算程序化。

### 3. 鲁棒

只给留下且必要的步骤加防护：幂等重试、`tests/` 断言、坑写 `docs/faqs/`。禁止给将被删除的步骤加 retry。

### 4. 加速

只缩短留下步骤的循环：少重复读文件、无依赖则并行、能缓存则缓存。加速一个本该删除的步骤 = 浪费。

### 落盘

禁止只写「下次注意」而不改文件。有变更才动：

- 业务工作流的删步 / 换入口 → 改 `docs/workflows/<slug>.md`（**不是** `builtin-workflows/`）
- 新脚本：未达升格门槛进 `temp/<主题>/`；确认会复用再进 `scripts/` / `src/` / `skills/`
- 新断言进 `tests/`；新坑进 `docs/faqs/`；登记 `docs/doc_index.md`
- 白痴指数 < 2 且无失败 → 明确「跳过落盘」，不造空文档

## 产物

- 更新后的业务 `docs/workflows/<slug>.md`（若有删步 / 换入口）
- 可选：`scripts/` / `tests/` / `docs/faqs/` / `temp/<主题>/` 中的程序化或防护产物
- **不是**反思散文；仓无文件变更且明确跳过落盘，也算合法结束

## 失败排查

| 现象 | 处理 |
|---|---|
| 写了一大段「下次注意」，仓没变 | 回到落盘规则：有变更才改文件；否则写「跳过落盘」并停 |
| 任务结束后自动跑了本流 | 停；本流仅用户明确要求时触发 |
| 纯问答无落盘却走了全流程 | 按 AGENTS 跳过条件退出；本流不该跑 |
| 先自动化 / 加速，再问该不该存在 | 停；回到步骤 1 删，顺序不可颠倒 |
| 把业务复跑流程新建进 `docs/builtin-workflows/` | 移到 `docs/workflows/`；builtin 只改已有内置文，且须有 AGENTS 触发 |
| 在本流里再次触发本流 | 套娃；直接结束 |

## 测试

同类任务再跑一轮时，至少满足其一：

- 步骤数或 LLM 调用次数下降
- 新断言能拦住上次的失败
- 白痴指数读数下降（同一计量口径）
